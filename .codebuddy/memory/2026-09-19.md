# 2026-09-19

## Meizu 设备上 app 打开全白屏 — 定位与修复

**现象**：Meizu `381QYGEM226CZ` 上安装 debug APK（来自功能分支 `codex/reader-own-tap-longpress`）后，
一打开就是纯白屏；a11y 树（`uiautomator dump`）能读到完整首页/设置页内容，点击 tab 也有效。

**定位过程（可复用）**：
1. 截图为全白（PNG 仅 31KB，正常界面 300KB~1.7MB）→ 用 `screencap -p` 文件大小即可快速判断"白屏 vs 有内容"。
2. `adb shell dumpsys activity <pkg>` 能输出该包 Activity 的完整 **View Hierarchy**（`dumpsys activity top`
   在这台 Flyme 上不一定包含目标 Activity）。
3. DecorView 直接子 View 末尾出现一个**无 id 的全屏 `android.view.View{... 0,0-1080,2400}`** →
   排除 `enableEdgeToEdge()` 的 `SystemBarStateMonitor$1` / `ProtectionLayout`（androidx.core，属正常）后，
   只剩 `EinkScreenRefresh` 一处会往 DecorView 加 View。
4. 触发前后台切换后**立刻** dump：全屏 View 数量 1 → 2，稳定后又回 1 —— 说明每次 `onResume` 都会加一个遮罩层。
5. 连拍截图（每组第 1 张有内容、之后变白）证实"切回前台先正常、随即被白色遮罩盖死"。

**根因**：`MainActivity.onResume()` → `EinkScreenRefresh.refresh()` 在 **所有设备**上都执行墨水屏
"全屏白→黑翻转"遮罩：`decor.addView(whiteOverlay)` + `overlay.postDelayed { 变黑; postDelayed { removeView } }`。
首次 `onResume` 时 DecorView 还没 attach 到 WindowManager，`View.postDelayed` 的 runnable 走了
RunQueue 路径；该白色遮罩**始终没被移除**，永久盖死界面（Meizu 没有 eink 服务，本就不该走这条回退路径）。

**修复**（`features/eink/EinkScreenRefresh.kt`）：
- `refresh()` 开头加 `hasEinkService()`（反射 `ServiceManager.getService("eink")`），非墨水屏设备直接 return。
- `overlayRefresh()` 改用显式 `Handler(Looper.getMainLooper())` 做"变黑/移除"，且 `decor.isAttachedToWindow` 为 false 时跳过；
  移除用 `(overlay.parent as? ViewGroup)?.removeView(overlay)`。

**验证**：修复版 APK 安装后，冷启动 + 前后台切换截图均正常显示（书库界面），DecorView 残留全屏 View 数量 = 0。

**未落地**：当前工作区在 `main` 上处于未完成的 `merge upstream/main` 状态（冲突已解决但未 commit），
且 `main` 里没有 `features/eink/`（该功能只在 `codex/reader-own-tap-longpress`），所以修复**没有写进仓库**。
构建是在工作区外的临时副本做的：`D:\AndroidCache\tmp\hoshi-fix`（`git archive codex/reader-own-tap-longpress` 解压 +
copy `local.properties` + `robocopy` 子模块 `third_party\hoshidicts-kotlin-bridge`，因为 CMake 依赖它的
`app/src/main/cpp/hoshidicts`，缺了会让 `configureCMakeDebug` 失败）。修复后的源文件备份在
`D:\AndroidCache\tmp\EinkScreenRefresh.fixed.kt`；APK 在 `D:\AndroidCache\tmp\hoshi-fix\app\build\outputs\apk\debug\app-debug.apk`。
后续需在 `codex/reader-own-tap-longpress` 上提交这份修复（或 merge 进 main 后再修）。
