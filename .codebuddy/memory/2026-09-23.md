## 修复：VN 双击句子翻译显示"别句的译文"（用户反馈）

- 现象：VN 模式下双击某句触发翻译，插入到该句下方的译文却是同章其他句子的译文。
- 根因（id 不稳定 + 章内缓存）：`reader-translation.js` 的 `ensureTargetId(element, index)` 用**当前屏 clone 的遍历序号**发 id（`hoshi-translation-1..N`），而 `ReaderWebView.kt` 的 `currentPageTranslationChapterKey = "$bookId:${readerPosition.loadPosition.index}"` 只含**章索引**（`loadPosition.index` 是 chapter index），`ReaderPageTranslationCoordinator` 的译文缓存 `translatedByChapter[chapterKey][targetId]` 在整个章内保留 → VN 每次翻屏 `screen.replaceChildren()` 重建 clone（`reader-visual-novel.js: renderScreen`），新屏段落又从 `hoshi-translation-1` 重新编号 → 双击新屏句子直接命中别屏同序号的缓存译文（`revealReaderPageTranslation` 先查 cache）。旧屏译文块内容因此被套到当前句上。
- 修法（按 AGENTS「VN 身份必须来自 source stream」）：
  1. `reader-visual-novel.js` 新增 `translationTargetKeyForElement(element)` + `sourceDepthForElement(element)`：用元素内**首个正文文本节点**的章内 raw offset（`this.nodeStartRawOffsets`，`buildNodeOffsets` 逐屏重建，key 为当前屏文本节点）+ 结构层级 + tagName 组成稳定 key（`vn-<raw>-<depth>-<tag>`），保证同一源段落跨屏同 id、嵌套候选（blockquote/p）也不同 id。
  2. `reader-translation.js` 新增 `stableTargetId(element)`：`global.hoshiReader.translationTargetKeyForElement` 存在时优先用其返回 key，否则回落原序号（分页/连续模式行为不变，元素常驻 DOM 本来就稳定）。
- 验证：新增回归测试 `reader-visual-novel.test.mjs`「visual novel translation target ids stay unique across screens of one chapter」（同 id⇒同原文 + 3 屏 3 个不同 id）。**已确认该测试在旧逻辑下会失败**（临时把 `stableTargetId` 改成 return null 跑出 `expected: '第二段落。'`），恢复后 13 个 reader JS 测试全过（VN 89 项）。CHANGELOG 合并进 Unreleased 的 Reader Translation (AI) Added 条目；装机 Meizu `381QYGEM226CZ` 成功。
- durable 提醒：VN 里任何"跨屏复用"的 key（译文缓存、朗读锚点 `lastReadAloudParagraphId`、书签）都不能用屏内序号 id。

## Meizu 20 系统语言：确认无法通过 adb 加日语（非本仓库代码）
- 需求：用户希望把 Meizu 20 系统语言改为日语（"安装语言包"）。
- 结论：Android 没有"下载语言包"机制。该机 Flyme 国行 ROM 只内置 8 种语言。语言设置页（`am start -a android.settings.LOCALE_SETTINGS` + uiautomator dump）只有 简体中文 / 繁體中文 / 繁體中文(香港) / English(US) / English(UK) / Русский / Español / العربية；dump 里 `scrollable="true"` 计数为 0、无 RecyclerView ⇒ 列表完整，不是滚动截断。
- 实证（决定性）：用 `aapt2 dump configurations`（build-tools 36.1.0）检查 `/system/framework/framework-res.apk` 与 `/system_ext/priv-app/Settings/Settings.apk`，语言配置只有 `ar, ar-rEG, es, es-rES, ru, ru-rRU, en, en-rUS, en-rGB, zh-rCN, zh-rTW, zh-rHK`，**完全没有 `ja`**。框架层和 Settings 都没有日语字符串 ⇒ 即使强制 locale=ja-JP，系统 UI 也只会 fallback 到默认语言（英文），不会变日语。
- 尝试并已回滚：`adb shell settings put system system_locales ja-JP` 写入成功，但 `dumpsys activity top` 的 `mGlobalConfig` 仍是 `[zh_CN]`、`persist.sys.locale` 仍是 zh-CN ⇒ 未生效（该机不经 LocaleManager 不重算配置）。已回滚 `system_locales` = `zh-CN`，设备恢复原状。
- `adb shell cmd locale` 只有 `set/get-app-locales`、`set/get-app-localeconfig`（Android 12+ per-app language），**没有**系统级/语言包安装子命令。
- 可行替代：① per-app 日语 `cmd locale set-app-locales <pkg> --locales ja-JP`（仅对自带 ja 资源的 App 生效，系统 UI 仍中文）；② 装日语输入法 App；③ 装日语 TTS 引擎（与系统语言无关）；④ 真·全系统日语需 root + locale 模块，或刷国际版 ROM（会清数据、风险高）。已把选项交给用户。

## 突破：系统 locale 成功改为 ja_JP（Meizu 20，无 root）
- 用户给出知乎《魅蓝手机flyme如何设置日语等其他语言》(zhuanlan.zhihu.com/p/32422156)。该文自己的前提就写着「即使设置成其他语言之后，系统设置里也只能看到英语，并不是所有 app 的菜单都会变为相应的语言」，其目的只是让 **App 按系统语言切换地区行为**（例：Kindle 连日区），并非系统界面日语。抓不到正文（知乎 403），靠搜索片段还原其方法：装 MoreLocale 2 → 开发者选项开 USB 调试 → `adb shell` → `pm grant jp.co.c_lis.ccl.morelocale android.permission.CHANGE_CONFIGURATION` → 在 App 里选「日本語(日本)」。
- 核实：`dumpsys package android` 里 `CHANGE_CONFIGURATION` 为 `prot=signature|privileged|development|role` ⇒ **development 级，adb 可授予**，文章原理成立。但本机没装 MoreLocale 2（2018 年的 `updateConfiguration` 实现未必兼容 Android 16）。
- 找替代：Qiita《ANDROID の端末の言語設定をコマンドで変更したい》实测三连败——`setprop persist.sys.locale` 无效、`com.android.customlocale2` 广播无效（该包已不预装）、`am start LOCALE_SETTINGS` 只是跳页面；作者可行方案是 **Appium Settings**（`pm grant io.appium.settings android.permission.CHANGE_CONFIGURATION` + 广播 `io.appium.settings.locale --es lang ja --es country JP`，免重启）。
- **最终采用的最省事方案（成功）**：
  1. `adb shell settings put system system_locales ja-JP`（写入成功）。
  2. `adb shell setprop persist.sys.locale ja-JP` → **Failed to set property**，shell 无权限，此路不通。
  3. `adb reboot` + 等待 ~50s → `adb shell cmd activity get-config` 与 `dumpsys activity` 的 `mGlobalConfig` 变为 **`[ja_JP]`**。
- 生效机制（durable）：AOSP `ActivityManagerService.retrieveSettings()` 在**开机时**调用 `Settings.System.getConfiguration` → `adjustConfigurationForUser()` 读 `Settings.System.SYSTEM_LOCALES` 写进全局 Configuration。所以 **`system_locales` 必须配合重启**；只写不重启 `mGlobalConfig` 不变（本次再次实测确认）。
- 实测后果：Settings 界面变**英文**（dump 出 `text="Languages"`），语言列表仍只有原来 8 种、无日语；截图存 `.codebuddy/locale_after_ja.png`。符合文章描述。已告知用户可一键回滚（写回 `zh-CN` + 重启）。
- durable 提醒：Android 上「系统界面语言」= ROM 内置资源，无语言包可装；能改的只是 **locale**，两者别混为一谈。

## 突破 2：「区域 & 语言+」把系统 locale 即时切成 ja_JP（免重启）
- 用户给贴吧链接（`tieba.baidu.com/p/7433413950`，403 抓不到正文）并把工具下到 `H:\日抓`：`区域 & 语言+.apk` + `platform-tools_r31.0.2-windows.zip` + 两个日语音声目录（三桥渡/一条，含 wav/vtt/txt/mp3）。
- APK 事实：包名 `com.sightidea.setlocale`（Locale & Language+ 5.1.0），targetSdk **17**，唯一权限 `CHANGE_CONFIGURATION`（**无 INTERNET**），入口 `com.sightidea.locale.LocaleActivity`，列表按 ICU 全集给出（**有** 日本語(日本)，而 Flyme 设置页列表没有）。
- 步骤（Meizu 20 `381QYGEM226CZ` 实测成功）：
  1. `adb install -r --bypass-low-target-sdk-block "H:\日抓\区域 & 语言+.apk"` —— Android 14+ 默认拒装 targetSdk<23，必须带该 flag。
  2. `adb shell pm grant com.sightidea.setlocale android.permission.CHANGE_CONFIGURATION` → `granted=true`（该权限含 `development` 保护级，adb 可授予）。
  3. `am start -n com.sightidea.setlocale/com.sightidea.locale.LocaleActivity` → 点 `日本語 (日本)`（bounds `[123,1809][491,1892]`）。
- 结果：**无需重启即时生效**——`settings get system system_locales`=ja-JP，`dumpsys activity` 的 `mGlobalConfig` 立刻变 `[ja_JP]`，logcat 里 `com.meizu.flyme.launcher` 的 `AssetManager2 locale list changing from [] to [ja-JP]` 说明 App 在热重配。走的是 `updatePersistentConfiguration`（直改全局 Configuration 并持久化），比 `settings put system system_locales`（必须重启）强。
- 但**系统界面仍无法日语**（本次逐项复查）：`aapt2 dump configurations` 对 `framework-res.apk`(414 项) / `SystemUI.apk`(147) / `Settings.apk`(109) / `FlymeLauncher.apk`(71) 全部 **NO ja**，只能 fallback 英文。设置首页那串「ユーザー715397672」不是界面日语化的证据，而是 Meizu 账号默认昵称等运行时数据（Settings.apk 内不存在任何日文字符串）。真正变化：`Locale.getDefault()`=ja-JP，自带 ja 资源的第三方 App 与日期/数字格式按日本走。
